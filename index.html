How it works

  1. Send audio. MP3, M4A, WAV, FLAC, MP4, MOV, OGG — upload via the API or a simple link. Up to 2 GB per file.
  2. Transcription runs. Our GPU pipeline transcribes with word-level timestamps and speaker-friendly punctuation, at many times faster than realtime.
  3. Get text + subtitles. Plain text, SRT/VTT subtitle files, or structured JSON with timestamps — via callback URL or download link.
  4. Source deleted. By default your audio is deleted after delivery. Longer retention on request.

For developers

One POST to upload, one GET for the result. API keys are free to create during the launch window.

# 1. upload — POST /v1/transcribe
curl https://subs.upscalemultimedia.com/v1/transcribe \
  -H "Authorization: Bearer $API_KEY" \
  -F "file=@meeting.mp3" \
  -F "lang=hu" \
  -F "format=srt,json"

# 2. result — GET /v1/jobs/{id}

Questions

Where is my audio processed?

On our own GPUs in the EU. No US cloud, no third-party ASR vendor. After delivery we delete your source file by default, and we never use customer audio for model training.

Which languages work best?

Hungarian, English, German, French, Italian, Spanish, Polish, Czech, Romanian and most major European languages. We support 30+ languages — for anything we're unsure about, send a 30-second test clip first and we'll tell you honestly.

What do you use under the hood?

faster-whisper large-v3 class models (open weights, run locally) with Hungarian-specific decoding and a two-pass timestamp refinement. All inference happens on our hardware.

Subtitles or just text?

Both — SRT and VTT with word-level timing plus plain text, or structured JSON with per-word timestamps if you're building something.

How fast is "fast"?

An hour of audio typically finishes in 2–5 minutes on our GPUs — far below realtime, even for long recordings, during normal load.
